# Практическая работа №2. Путь программы: IL, HEX и Debug vs Release

## Результаты замера Debug vs Release

| Режим | Запуск 1 | Запуск 2 | Запуск 3 | Запуск 4 | Запуск 5 | Минимум |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| Debug | 1886 мс | 1924 мс | 1850 мс | 1891 мс | 1862 мс | **1850 мс** |
| Release | 450 мс | 411 мс | 438 мс | 425 мс | 432 мс | **411 мс** |

В моем эксперименте Release режим отработал быстрее, чем Debug, примерно в 4,5 раза. Так получилось, потому что при сборке Release компилятор включает оптимизацию кода и убирает лишние операции, которые нужны только для отладки.

## Что я обнаружил при сравнении IL

- В конфигурации Debug куча инструкций `nop` (пустые операции для отладчика), в Release их вообще нет.
- В Release методе код стал компактнее, потому что компилятор убрал лишние промежуточные сохранения и загрузки локальных переменных (строки `.locals init`, `stloc` и `ldloc`).
- Количество IL-инструкций в методе `Add()` уменьшилось с 12 штук (в Debug) до 4 штук (в Release).

## Ответы на контрольные вопросы

1. **Что такое IL и зачем он нужен между C# и машинным кодом?**
   IL — это промежуточный код (байткод), в который превращается C# после компиляции. Он нужен для независимости от железа. Ему плевать, какой процессор стоит на компе — x86 или ARM. А уже при самом запуске программы JIT-компилятор переводит этот IL-код в понятные конкретному процессору машинные команды.

2. **Почему .dll можно декомпилировать?**
   Потому что .NET сборки (файлы .dll) хранят внутри не просто байткод, а еще и метаданные — полную информацию о всех классах, типах и методах. Если открыть такую библиотеку через ILSpy, утилита легко прочитает эти данные и восстановит исходный читаемый код на C#.

3. **Какие отличия Debug и Release вы увидели в IL?**
   Код в Release выглядит намного короче. Там нет пустых инструкций `nop` и убрана лишняя возня с переменными в памяти.

4. **Почему Release обычно быстрее Debug?**
   Потому что в Release компилятор настраивает код на максимальную производительность. Он вырезает всю отладочную информацию, которая тормозит программу, и оптимизирует циклы.

5. **Почему строковый пароль в .dll нельзя считать защищенным?**
   Обычная компиляция в .dll — это не шифрование. Все строки и текстовые пароли лежат внутри файла в открытом виде (кодировка UTF-16). Если открыть этот файл через простой HEX-редактор типа HxD или декомпилятор, любой человек сможет спокойно прочитать этот пароль.
